# Activation-by-Activation State Log

**Optional project worksheet.** You can play your first learning game without filling this in. Use the [beginner scenario](./first-learning-scenario.html), [setup sheet](./first-game-setup-sheet.html) and [first-game checklist](./first-game-checklist.html) to learn the game first. This log is for a later replay, or for a game where you deliberately want to collect data for the AI-table project.

## One row means one Operator activation

A round contains four activation phases, followed by Upkeep. A phase can contain more than one Operator activation. **Record a separate state after each Operator finishes activating**; do not treat a whole phase as one activation. The three numbered slots below are capacity, not a requirement to activate three Operators. Follow the current rulebook for who may activate and how many.

## How to record a useful state

- Use the same position notation throughout the game: a printed space/coordinate if available, otherwise a consistent room-and-space description.
- Record facing with the board's direction/arrow or a consistent N/E/S/W convention.
- In each team-state field, list every Operator still in play, not just the Operator that just activated. A compact format is fine, for example: `Ash=Lobby-C3/E; Sledge=Outside-B1/N; wounds 0; available`.
- Include relevant status markers, activation-used state, gadgets, destroyed/barricaded terrain, and objective/control state. Write `unchanged` only if the previous row still describes that part of the board.
- If you are playing Attackers and want to preserve hidden information, do not inspect or record the Defender's true token identities during play. You can add the hidden-state details from the Defender's notes after the game.

## After the session

1. Which rule was hardest to apply consistently?
2. Which state detail was easiest to miss: position, facing, wounds/status, activation state, terrain/gadgets, or objective?
3. Which state needs a rulebook or FAQ check before it can become a reliable automated test?

**Rule priority:** this is a project data-collection aid, not a rules source. If it conflicts with the current rulebook, mission material, Operator profile or FAQ/errata, follow the official material.
